Colophon · how this site is made

Built by hand

Every portfolio claims its owner writes good code. This page is the part you can check. The site you are reading has no framework, no animation library and nothing to install — the scroll, the pinning, the wipes and the spider on the contact page are all written here, in files you can open. What follows is how, and what it cost.

The rig

RIG.track(section, fn)

0.000

That number is the only input any effect on this site receives: how far the reel has run through the section you are in, from 0 to 1. The words lighting up one by one, the project plates wiping across, the process steps cross-fading — each is a small function of this, and nothing else. No timeline, no keyframes, no library holding state.

The parts
01

The scroll

scroll.js · 10 KB

The wheel is intercepted and the page eased toward a target rather than jumped to it. Sections are pinned with CSS sticky — the engine never writes layout, only reads it.

02

The choreography

main.js · one pass per frame

Every act is a guard-claused block: if its markup is absent the block does nothing. That is why the same file drives every page on this site without a single condition about which page it is on.

03

The hero

reveal.js · canvas

The portrait is two layers — a latent ghost and a developed print — and the pointer wipes the second up over the first, decaying behind you like a print coming up in a tray.

04

The web

web.js · 775 strands

The contact page carries an orb web that ripples where your cursor passes, and a spider that hunts the vibration. All 775 strands are stroked as one path, which took the frame cost from 0.85ms to 0.17ms.

05

The leader

leader.js · 10 → 0

The countdown always takes its full run, even from a warm cache, and never shows zero until the page has genuinely finished loading. So zero always means ready — it is a real signal, not a decorative delay.

06

The chrome

build-pages.js

The film edge, reel index, playhead and footer are written into every page from one source. Pages stay plain files you can open from disk — the build syncs them, it is not needed to serve them.

What it cost

The honest part

What this buys

Nothing to update and nothing to audit. No build to run before the site will load. A page weight measured in kilobytes, and behaviour I can explain line by line — including to whoever maintains it after me.

What it costs

Time. A scroll engine is a solved problem and I solved it again. On a client project I would reach for the library, because their budget should buy their features, not my scroll behaviour. This site is where the exception is worth it.

Where it gives way

Reduced-motion turns the whole choreography off and leaves a plain document, which is the correct answer. Pointer effects need a fine pointer, so touch gets the static layer. Without JavaScript the content still reads; the motion simply is not there.
